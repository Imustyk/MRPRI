**Дата:** 2026-11-09 · **Ветка:** `feature/risk-specific-detection` (HEAD `aa970da` и новее, локально, без push)
**Статус:** план. Результаты экспериментов — отдельный документ `reports/MTA-0020_RESULTS.md`,
который создаётся **только после** выполнения реальных расчётов.

## 1. Цель и границы

Цель MTA-0020 — **независимое воспроизводимое сравнение** методов обнаружения
аномалий на одинаковых условиях и честный ответ на исследовательскую гипотезу
(§2). Границы, зафиксированные до начала экспериментов:

1. **Production v0 не изменяется.** Не трогаются `scripts/00..11`,
   `src/mtender/**`, `backend/**`, `frontend/**`, `data/raw/**`,
   `results/tables/tender_anomaly_scores.csv`,
   `results/models/anomaly_models.joblib`, `data/features/features.csv`
   (152 378 строк, одна строка на OCID). Сравнение — измерение, а не ретренинг
   продакшена.
2. **Неподтверждённые метки ANSC не используются как ground truth.** На
   2026-11-09 ручная проверка выполнена для **1 из 50** документов, внешняя
   метка `ansc_upheld` не существует
   (`data/external/ansc_upheld_labels.csv` отсутствует; шлюзы
   `scripts/46 validate`/`45`/`47` обоснованно выходят с кодом 5).
3. **Отрицательный результат — результат.** Если простые индикаторы окажутся
   лучше ансамбля, это будет зафиксировано как научный вывод (прецедент:
   `docs/EXPERIMENTAL_MODEL_COMPARISON.md` — H1 отклонена на обеих внешних
   метках, внедрение не принято).

## 2. Гипотеза и три допустимых результата

**H (MTA-0020):** «Комбинация методов обнаружения аномалий и специализированных
индикаторов коррупционных рисков обеспечивает более информативное выявление
потенциально проблемных государственных закупок по сравнению с простыми
статистическими методами».

Гипотеза **проверяется, а не предполагается**. Допустимы ровно три исхода:

1. гипотеза подтверждается на независимых данных;
2. гипотеза не подтверждается;
3. доступных данных недостаточно для достоверного вывода — тогда публикуется
   точная формулировка:
   `Insufficient independent external labels for reliable model comparison.`

Формулировки «обнаружена коррупция»/«доказано нарушение» на основании одних
аномалий запрещены; каждая таблица сопровождается дисциплеймером из шапки.

## 3. Сравниваемые конфигурации

Четыре конфигурации, differing только блоком скоров; все остальные условия
идентичны (§4):

| Арм | Конфигурация | Источник скоров | Роль |
|---|---|---|---|
| **Baseline 1** | простые статистические индикаторы | `BASELINE_SPECS` (`scripts/35_external_validation.py` L96): `amount`, `n_bidders_fewer`, `value_within_cpv`, `single_bidder`, `random` — направления зафиксированы до расчёта AUC и никогда не переворачиваются | нижний ориентир |
| **Baseline 2** | отдельные детекторы | MAD (`scripts/06_detect_anomalies.py::statistical_baseline`, L62), Isolation Forest (L162), LOF (L180), OCSVM (L198) — по одному скору каждый | вклад каждого метода |
| **Baseline 3** | существующий voting ensemble v0 | `fit_ensemble` (`scripts/20_cycle_framework.py` L421): votes ≥ 3, `max_score` = max percentile rank | продакшен-ориентир |
| **Experimental** | специализированные риск-индикаторы | `src/mtender/risk_modules.py` (`competition/splitting/network/value_distribution_indicators`, `module_indicators` → `n_module_hits`) | тестируемая гипотеза |

Правило: **направления всех скоров — pre-registered** (см. `BASELINE_SPECS` и
guard-тест `test_directions_are_pre_registered`); ни один скор не
переопределяется и не пере-порогуется после взгляда на метрики.

## 4. Единый протокол (одинаковые условия для всех четырёх арм)

### 4.1 Единица наблюдения

Одна строка = одна процедура (OCID), `data/features/features.csv`, 152 378
строк, 22 признака `src/mtender/features.py::FEATURE_COLUMNS`. Для
документных меток (ANSC) — **независимая единица = уникальный документ/OCID**:
50 URL выборки = 44 уникальных PDF = 44 независимые процедуры
(`scripts/45_ansc_review_metrics.py::sample_independence`; группы побайтовых
дубликатов [8,9,10], [16,17], [22,26], [40,43,48] учитываются один раз —
повторные URL не раздувают знаменатель).

### 4.2 Временное разбиение

**TUNE 2018–2021 / TEST 2022–2024**, ключ — `published_date`
(`scripts/14_threshold_calibration.py` L44, L124). Все пороги, k-бюджеты и
выборы конфигураций — только на TUNE; TEST используется один раз для финального
отчёта.

### 4.3 Правила дедупликации

- в основном корпусе — одно наблюдение на OCID (уже выполнено схемой
  `features.csv`);
- в документной выборке ANSC — SHA-256 группировка побайтовых дубликатов
  (44 независимых документа из 50 URL);
- связанные процедуры одного заказчика/поставщика — кластеризация для
  бутстрапа (см. §7), а не для удаления.

### 4.4 Признаки и нормализация

- Набор признаков одинаков для всех четырёх арм: 22 колонки
  `FEATURE_COLUMNS`. Риск-модули используют те же доступные колонки
  (`src/mtender/stage_features.py`); их `future_*`-индикаторы
  (`future_confirmation_indicators`) — **только evaluation-only**, никогда не
  входят в скор кандидата в продакшен-сравнение без явной пометки
  «ретроспективный».
- `LABEL_ONLY_FIELDS` (`aap_label`, `ansc_label`, `complaints`, `sanction`,
  `planted_pattern`, `is_planted_anomaly`) **никогда не бывают признаками**
  (guard `scripts/33_temporal_leakage_audit.py`, тест
  `test_labels_are_never_features`).
- Нормализация: `StandardScaler` внутри TUNE (как в `fit_ensemble`); для
  rank-based скоров (MAD max-z, percentile-ранги) — ранжирование на TUNE,
  перенос на TEST без пересчёта распределения TUNE-периода.
- Стадийная осведомлённость: `src/mtender/stage_features.py` +
  `docs/TEMPORAL_LEAKAGE_AUDIT.md` — при сравнении сообщается, какие из 22
  признаков point-in-time safe на стадии `award_decision`/`post_award`.

### 4.5 Внешние метки

См. таблицу доступности §5. Одна и та же метка используется во всех четырёх
армах одновременно; смешение разных меток в одном сравнении запрещено.

### 4.6 Процедура оценки

ROC-AUC (только когда определены оба класса), PR-AUC, P@K, R@K, Lift@K при
бюджетах K ∈ {100, 500} (`K_VALUES`, `scripts/35`), кластерный bootstrap
B=1000, seed=42, paired Δ между армами на общих replicate-выборках,
стабильность по периодам и заказчикам, согласованность детекторов
(`scripts/13_agreement_matrix.py`). Минимум 30 positives на подпериод, иначе
периодная AUC не публикуется (`MIN_POSITIVES_TEMPORAL`).

## 7. Метрики и статистическая отчётность (Этап 7)

- ROC-AUC — только при определённых обоих классах; PR-AUC как основной
  metric при малом base rate; P@K, R@K, Lift@K (K=100, 500).
- **Bootstrap-ДИ**: кластерный percentile bootstrap, B=1000, seed=42, кластеры
  = поставщик (AAP) / заказчик (ANSC); paired Δ между армами на общих
  replicate-выборках.
- Стабильность: по периодам (2018–2021 vs 2022–2024) и по заказчикам;
  согласованность детекторов (agreement matrix, Cohen's κ, votes-распределение).
- Запреты: **порог не выбирается на TEST**; **модель не подбирается по
  финальным внешним меткам**; направления не переворачиваются; результаты при
  малом числе подтверждённых случаев не представляются как статистически
  надёжные (min 30 positives на подпериод, иначе — не считать).

   результата + новые arm-сравнения.
3. Разрезы «все 22 признака vs point-in-time safe», «fit-on-TUNE vs as-is» —
   sensitivity-анализ утечки №2/№5.

**Заблокировано (не выполнять до данных):**

1. Сравнение с ground truth `ansc_upheld` — до завершения ручной разметки
   MTA-0019 (сейчас 1/50).

   допустимых экспериментов.
3. Любой из 46/45/47 шлюзов с подсчётом метрик — до **всех** человеческих
   подтверждений.

Если к моменту финального вердикта независимых сильных меток недостаточно —
