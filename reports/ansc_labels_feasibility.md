# MTA-0012: разведка меток ANSC внутри сырых данных MTender — отчёт о выполнимости

**Индикатор потенциального риска, а не доказательство коррупции/нарушения.
Требуется проверка компетентным органом.** Любая метка «жалоба удовлетворена»
ниже по тексту — слабый операционный сигнал, а не факт нарушения.

Цель: выяснить, можно ли получить независимую слабую метку «процедура
оспорена, жалоба удовлетворена» из документов, на которые сырые OCDS MTender
уже ссылаются, **не обращаясь к сайту ANSC**. Это отчёт о выполнимости, а не
метка в модели: без обучения, без новых циклов, бюджет остаётся 6 из 10,
production — v0.

Инструменты: `scripts/29_ansc_docs_inventory.py` (часть A, локально, только
чтение `data/raw/**`), `scripts/30_ansc_sample_parse.py` (часть B, сеть;
отказывается работать без явного `--allow-network`, запускался как
`python -I`). Артефакты: `results/methodology/ansc_docs_inventory.json`,
`results/methodology/ansc_sample_parse.json`,
`results/tables/ansc_docs_inventory.csv` (все документы),
`results/tables/ansc_candidates.csv` (кандидаты).

## Часть A. Инвентаризация документов (152 378 пакетов, локально)

Общее число документов в сырых OCDS: **430 959** (по уровням: tender
342 220; award 68 377; contract 20 362; planning — 0, блоки planning в
сырых пустые). Все ссылки ведут на один хост: `storage.mtender.gov.md`
(430 944 из 430 959; 15 документов без хоста в url).

Распределение `documentType` (топ): biddingDocuments 255 025;
evaluationReports 38 738; tenderNotice 36 478; technicalSpecifications
32 229; awardNotice 17 393; winningBid 15 562; **complaints 6 970**;
cancellationDetails 5 406; eligibilityCriteria 4 946; contractSchedule
4 448. Самые частые title — шаблонные файлы закупок (`duae.doc` 8 884,
`anunt de participare.pdf` 4 512, `caiet de sarcini.pdf` 3 085 …), то есть
шум; ANSC-документы в топ-25 не попадают.

Структурные поля (вне `documents`): массив `complaints` в сырых не
встречается ни на одном уровне; `enquiries` (факт запросов) есть у 19 810
тендеров; `amendments` — у 26 462 тендеров и 2 676 контрактов. То есть
единственный структурный след обжалований — `documentType = complaints`.

Ключи (регистронезависимо, с нормализацией диакритики — «contestați» ловит
«contestaţie»/«contestație»), сопоставлялись с title + description + url:

| `Agenția Națională pentru Soluționarea Contestațiilor` | 2 | 2 |
| `жалоб` | 1 | 1 |
| `Autoritatea Națională pentru Soluționarea Contestațiilor` | 0 | 0 |
| `hotărâre ANSC` | 0 | 0 |
| `решение АНСК` | 0 | 0 |
| структурный: `documentType = complaints` | 6 970 | 1 665 |

Объединение всех кандидатов (включая слабый `decizi`): 27 447 документов /
7 824 процедуры. **Сильные кандидаты** (всё, кроме `decizi`, плюс

ссылками на `03D-…`, 1 665 — с документами типа complaints (полное
пересечение со сильными), 67 — с явным «ANSC» в тексте. Пара из примера

2026 годом, а корпус охватывает 2018–2024; проверка парсера выполнена на
синтетических строках (`tests/test_ansc_parser.py`).

## Часть B. Пробная выборка и парсинг

Условия: **50 документов** (максимум по заданию), стратифицированно по годам,
сильные кандидаты первыми; последовательно, пауза **2 с** между запросами,
User-Agent с указанием учебной цели; загрузка только с
`storage.mtender.gov.md` (хост проверяется и в исходном url, и после
редиректа). Обхода ограничений не было: **50 из 50 скачано, ни одного
403/429, ни одного редиректа вне storage — остановка не потребовалась**.
Каждый файл лежит в собственной свежей папке вне репозитория
(`$TMPDIR/mtender_ansc_sample_20261018T085031Z/doc_NNN_<ocid>/`); ничего из
скачанного не исполнялось, текст извлекался только `pypdf` (запуск —
`python -I`).

**Извлечение текста: 35 из 50 (70%)** — PDF с текстовым слоем; **15 из 50
(30%) — сканы, помечены «требует OCR»**, OCR не запускался.

Извлечённые регулярными выражениями поля:

- **номера решений ANSC** — найдены в 3 документах: `03D-555-18`,
  `03D-1003-20`, `03D-801-21` (реальные решения, парсер работает на живых
  документах);
- **номера закупок `MD-…`** — в 13 документах (в каждом — собственный ocid;
  у одного документа — два ocid: `MD-1583219931679` и `MD-1586420119604`);
- **даты** `dd.mm.yyyy` — в большинстве документов;
- **исход** распознан у 7 документов: `admis` — 3, `respins` — 3,
  `admis_partial` — 1 (доля admis с частичным — 4 из 7);
- **номера жалоб/реестровые номера** (`1234b/05.04.2026`, `01-02-01/05/933/26`)
  в пробную выборку не попали — паттерны проверены на синтетических строках
  (`tests/test_ansc_parser.py`).

Пара из примера автора (письмо 01-02-01/05/933/26, решение 03D-159-26,
закупки MD-1771250199749 / MD-1772439133346) в корпусе отсутствует — это
2026 год, а корпус покрывает 2018–2024.

Оговорки: (1) исходы — эвристика по румынскому тексту; уведомление об отмене
(`instiintare anulare`) даёт `admis` по словам «admite…» в служебном тексте —
возможны ложные срабатывания, для метки нужна ручная валидация; (2) доля 4/7 —
сигнал с выборки в 50 документов, не оценка генеральной совокупности;
(3) в OCDS встречаются дубли записей (две процедуры несли по одному и тому же
документу дважды) — при построении метки нужен дедуп по `(ocid, url)`.

Персональные данные: полные тексты в репозиторий не попадали (лежат только в
песочнице вне репозитория); в артефакты сохранены только номера, даты,
идентификаторы закупок и исход.

## Часть C. Оценка пригодности метки

### Объём

Из части A: документы обжалования/решений ANSC-типа есть у **1 665–2 183
процедур — 1,09–1,43% корпуса 152 378** (нижняя граница — только
`documentType = complaints`, верхняя — все сильные ключи). Слабое объединение
с ключом `decizi` даёт 7 824 процедуры (5,1%), но это преимущественно шум
обычных решений о присуждении, не обжалования.

Если предположить долю исхода `admis` около 40–60% (по пробной выборке 4 из 7
с распознанным исходом; выборка мала), то «жалоба удовлетворена» потенциально
покрывает **~700–1 300 процедур — 0,5–0,8% корпуса**. Прямо фиксируем:
**метки недостаточно** — для обучения и даже для внешней проверки в духе AAP
(где 633 процедуры уже были маломощными) такой объём на порядок ниже нужного.
Использовать возможно только как редкий дополнительный индикатор на
пересечении с другими сигналами, с ручной валидацией исходов.

### Смещения (обязательны при любом использовании)

1. **Отбор на конкуренцию и обжалование.** Метка существует только там, где
   есть конкурс и поданная жалоба; прямые закупки (51,5% корпуса,
   `docs/model_card.md:109`) структурно не охвачены — по ним метка всегда
   «нет», и это не «без нарушения», а отсутствие наблюдения.
2. **Привязка.** Жалоба привязана к процедуре и заказчику, а не к
   поставщику: в отличие от метки AAP (поставщиковое приписывание) здесь
   нельзя без дополнительных допущений строить «поставщик-нарушитель».
3. **Смысл исхода.** «Жалоба удовлетворена» (admis) — решение о
   procedur­альном требовании заявителя, а не доказанное нарушение и не
   вина поставщика или заказчика; «отклонена» (respins) не означает
   отсутствия риска. Это индикатор потенциального риска, а не
   доказательство коррупции/нарушения — требуется проверка компетентным
   органом.
4. **Полнота публикации документов.** Документы жалоб выгружаются на
   storage выборочно и неравномерно по годам (2018 и 2024 — заметно
   беднее 2019–2023), часть файлов — сканы без текстового слоя (см. часть
   B), часть — не PDF.
5. **Дубли и форматы.** Одна процедура несёт несколько документов
   (контестация, уведомление, решение); без ручной валидации легко
   двойной счёт.

### Схема использования (если метка будет строиться)

- Единица метки — **процедура** (ocid), не поставщик: `procedure_contested
  = 1` при наличии документа типа complaints или решения `03D-…`;
  `complaint_upheld = 1` только при распознанном исходе `admis`
  (включая `admis_partial` — отдельной пометкой).
- Годность — только как **внешний слабый чек** (например, доля upheld
  процедур в high+ против корпуса), никогда как обучающая метка и никогда
  как критерий приёмки: покрытие ~1–2% и смещения выше делают обучение
  на ней бессмысленным.
- Хранить только нормализованные идентификаторы и исход, без текстов
  документов (персональные данные физических лиц в артефакты репозитория
  не собираются; полные тексты остаются в песочнице вне репозитория).

### Вердикт

**Частично.**

- **Выполнимо локально:** (а) идентифицировать процедуры с документами
  обжалования — 1 665 процедур по `documentType = complaints` (2 183 со
  всеми сильными ключами); (б) извлечь из текстов на storage номера решений
  `03D-…` и исходы — 70% документов дают текст, номера решений реально
  встречаются.
- **Невыполнимо локально:** (в) полный реестр решений ANSC за 2018–2024 — в
  сырых MTender есть только те жалобы, что стороны сами приложили к
  процедурам; сам реестр ANSC шире и включает дела, следы которых в OCDS
  нет; (г) сканы без текстового слоя (30% документов) — метка на них
  недоступна без OCR.
- **Следствие:** независимая слабая метка «процедура оспорена, жалоба
  удовлетворена» из локальных данных строится как **редкий и
  неоднородный по годам сигнал (~1% корпуса)** — этого мало для
  валидации модели; полная версия требует доступа к реестру ANSC.

## Что нужно от автора

1. **Доступ к реестру ANSC за 2018–2024** — ручная выгрузка с сайта ANSC
   или через BI-инструмент OCP: номера решений `03D-…`, исходы, ссылки на
   закупки. Это единственный путь к полной независимой метке: сырые MTender
   содержат только приложенные к процедурам документы.
2. **Решение по основе метки:** строить ли `procedure_contested` на
   `documentType = complaints` (1 665 процедур, уже сейчас локально
   идентифицируемы), а `03D-…`-ссылки (524 процедуры) использовать как
   подтверждение исхода.
3. **Санкция на OCR** 15 сканов из 50 (30% выборки) — либо согласие
   отбросить сканы при любом будущем построении метки.
4. **Подтверждение рамки использования:** метка — только внешний индикатор
   потенциального риска (не обучающая, не критерий приёмки), с формулировкой
   «требуется проверка компетентным органом».

## Воспроизведение

```bash
.venv/bin/python scripts/29_ansc_docs_inventory.py          # часть A, ~1 мин
.venv/bin/python -I scripts/30_ansc_sample_parse.py \
    --max-docs 50 --sleep 2 --allow-network                  # часть B
.venv/bin/python -m pytest tests/test_ansc_parser.py -q      # 15 тестов
```

Скачанные файлы не исполняются; каждый документ лежит в собственной свежей
папке вне репозитория (`$TMPDIR/mtender_ansc_sample_<timestamp>/`), полные
тексты в репозиторий не попадают.
