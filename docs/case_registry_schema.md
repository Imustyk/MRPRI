# Реестр случаев из открытых источников (MTA-0016) — схема

**Назначение.** Третья, независимая внешняя метка валидации: реестр случаев,
зафиксированных в открытых источниках (судебные решения, постановления
прокуратуры/НЦБКК, решения ANSC, списки AAP, отчёты Счётной палаты,
журналистские расследования). Случаи используются **только для проверки**
ранжирования v0 — не для обучения и не для перенастройки детекторов.
Production остаётся v0; `data/raw/**`, `backend/`, `frontend/`,
`scripts/00..11` не изменяются.

**Файл.** `data/external/case_registry.csv` — UTF-8, RFC-4180, одна строка =
один случай. Шаблон содержит только заголовок; записи вносит человек по
открытым источникам. Скрипт `scripts/38_case_registry_match.py` пересчитывает
сопоставление с MTender; заполненные в реестре столбцы `match_method`,
`match_confidence`, `n_procedures_matched`, `procedure_ids` перепроверяются
против пересчёта и расхождения выводятся в отчёт (не редактируются молча).

## Столбцы

| Столбец | Обязательный | Правило |
|---|---|---|
| `case_id` | да | уникальный идентификатор записи (напр. `C-001`) |
| `title_short` | да | короткое название случая **без имён частных лиц** |
| `entity_type` | да | `buyer` / `supplier` |
| `entity_id_mtender` | нет* | IDNO, нормализованный как в проекте: только цифры, без `MD-IDNO-` (напр. `1006601001182`) |
| `entity_name_as_in_source` | нет* | название юрлица **как в источнике** (латиница/кириллица/румынский — как написано) |
| `source_url_1` | да | URL первого источника |
| `source_type_1` | да | тип источника (см. рекомендуемые значения ниже) |
| `source_date_1` | да | дата источника, `YYYY-MM-DD` |
| `source_url_2` | нет | URL второго источника (второй источник настоятельно рекомендуется) |
| `source_type_2` | нет | тип второго источника |
| `source_date_2` | нет | дата второго источника, `YYYY-MM-DD` |
| `evidence_level` | да | `A` / `B` / `C` / `D` — см. определения ниже |
| `risk_type` | да | `collusion` / `price_inflation` / `fake_competition` / `splitting` / `short_deadline` / `other` |
| `period_from` | нет | начало периода эпизода, `YYYY-MM-DD` |
| `period_to` | нет | конец периода эпизода, `YYYY-MM-DD`; если заполнено — `period_from <= period_to` |
| `first_publication_date` | да | дата, когда случай стал публично известен, `YYYY-MM-DD`; участвует во временной защите |
| `match_method` | нет | заполняется/перепроверяется скриптом: `idno_exact` / `name_exact` / `name_fuzzy` / `manual` |
| `match_confidence` | нет | заполняется/перепроверяется скриптом: `high` / `medium` / `low` |
| `n_procedures_matched` | нет | число сопоставленных процедур (пересчитывается скриптом) |
| `procedure_ids` | нет | список сопоставленных `ocid` через `;` (пересчитывается скриптом) |
| `verified_by_human` | да | `true` / `false` — проверено ли сопоставление человеком |
| `notes` | нет | примечания (без персональных данных частных лиц) |

\* хотя бы один из `entity_id_mtender` / `entity_name_as_in_source` обязателен:
без идентификатора сопоставление невозможно.

Рекомендуемые значения `source_type` (свободный текст, не строгий enum):
`court_decision`, `prosecutor_order`, `ncbkk_decision`, `ansc_decision`,
`aap_list`, `chamber_of_accounts`, `journalism`, `other`.

## Уровни доказательности (`evidence_level`)

| Уровень | Определение | Входит в метку проверки |
|---|---|---|
| `A` | решение суда / постановление прокуратуры или НЦБКК / решение ANSC / список AAP | да |
| `B` | отчёт Счётной палаты | да |
| `C` | журналистское расследование | да |
| `D` | упоминание без документов | **нет — в расчёты не входит** |

## Правила приёмки записей

1. **Записи без источника не принимаются.** Строка без
   `source_url_1` + `source_type_1` + `source_date_1` (или без
   `first_publication_date`) отклоняется скриптом с указанием причины и не
   участвует ни в сопоставлении, ни в метке.
2. **`evidence_level = D` в расчёты не входит**: такие записи
   сопоставляются и показываются в отчёте, но никогда не образуют позитивов
   метки (`scripts/39`, тест `test_evidence_d_never_in_label`).
3. **Надёжность сопоставления.** Приоритет: IDNO (`idno_exact`, `high`) →
   точное название после нормализации (`name_exact`, `high`) → неточное
   совпадение (`name_fuzzy`) только как **кандидат** с
   `match_confidence = low`; автоматически в `high` не повышается никогда.
   Записи `low` в основной расчёт не входят и считаются отдельно.
   `manual` — сопоставление подтверждено человеком: используются
   объявленные `procedure_ids`, но только при `verified_by_human = true`.
4. **Временная защита** (`scripts/39`): в метку и в популяцию сравнения
   попадают только процедуры с `published_date` **строго раньше**
   `first_publication_date` случая. Признаки и оценки v0 из данных после
   этой даты **не пересчитываются** — используется фиксированный
   прод-артефакт `results/tables/tender_anomaly_scores.csv`; ограничение
   (поля наград в `features.csv` — снимок поздней даты) явно указано в
   отчёте.
5. **Запрет на выдумывание.** Реестр не наполняется автоматически и не
   дополняется сетью: `scripts/38` не выполняет сетевых запросов вообще, а
   флаг `--allow-network` зарезервирован и в текущей версии не открывает
   ни одного соединения.

## Рабочий процесс

1. Заполнить строку реестра по открытому источнику (минимум 1 источник,
   лучше 2; без персональных данных частных лиц).
2. `.venv/bin/python scripts/38_case_registry_match.py` — пересчёт
   сопоставления, отчёт `reports/case_registry_match.md`,
   артефакт `results/methodology/case_registry_match.json`.
3. `.venv/bin/python scripts/39_case_registry_check.py` — проверка v0
   против реестра (метрики, базовые ранжирования, случайные контролы,
   вердикт а/б/в по правилу ANSC-проверки), отчёт
   `reports/case_registry_check.md`.
4. `.venv/bin/python scripts/40_case_registry_studies.py` — разборы случаев
   (ранги 4 детекторов, голоса, SHAP/LIME топ-3, RAG-пояснение),
   отчёт `reports/case_studies.md`.
5. `scripts/19_final_verification.py` пересчитывает числа реестра из
   артефактов и **падает при любом расхождении**.

## Ограничения метки (указываются в каждом отчёте)

- Метка смещена к крупным и громким случаям; сравнение с базовым ранжированием
  «только размер» обязательно.
- Журналистские материалы (C) ≠ доказательство нарушения.
- Результат показывает приоритизацию, а не наличие коррупции.
- «Индикатор потенциального риска, а не доказательство
  коррупции/нарушения. Требуется проверка компетентным органом.»
