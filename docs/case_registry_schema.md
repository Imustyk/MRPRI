# Реестр случаев из открытых источников (MTA-0016/MTA-0017) — схема

**Назначение.** Третья, независимая внешняя метка валидации: реестр случаев,
зафиксированных в открытых источниках (судебные решения, постановления
прокуратуры/НЦБКК, решения ANSC, списки AAP, отчёты Счётной палаты,
журналистские расследования). Случаи используются **только для проверки**
ранжирования v0 — не для обучения и не для перенастройки детекторов.
Production остаётся v0; `data/raw/**`, `backend/`, `frontend/`,
`scripts/00..11` не изменяются.

**Файлы.**

| Файл | Роль | Наполняет |
|---|---|---|
| `data/external/case_registry.csv` | реестр случаев (26 столбцов, см. ниже) | человек **или** `scripts/41` |
| `data/external/case_sources.csv` | список источников (`source_id, url, source_type, publication_date, evidence_level, title, notes`) | человек (список даёт автор) |
| `data/external/case_episodes_raw.csv` | извлечённые эпизоды (13 столбцов, см. ниже) | человек (извлечение по MTA-0017) |
| `data/external/case_unmatched.csv` | эпизоды без привязки + причина (15 столбцов) | `scripts/41` |

Все четыре файла — UTF-8, RFC-4180, только заголовок в шаблоне.
`scripts/41_case_registry_ingest.py` превращает источники+эпизоды в строки
реестра (`link_basis` выводится, не выдумывается) и пишет несопоставленные
эпизоды в `case_unmatched.csv`. `scripts/38_case_registry_match.py`
пересчитывает сопоставление с MTender; заполненные в реестре столбцы
`match_method`, `match_confidence`, `n_procedures_matched`, `procedure_ids`
перепроверяются против пересчёта и расхождения выводятся в отчёт (не
редактируются молча).

## Столбцы

| Столбец | Обязательный | Правило |
|---|---|---|
| `case_id` | да | уникальный идентификатор записи (напр. `C-001`) |
| `title_short` | да | короткое название случая **без имён частных лиц** |
| `entity_type` | да | `buyer` / `supplier` |
| `entity_id_mtender` | нет* | IDNO, нормализованный как в проекте: только цифры, без `MD-IDNO-` (напр. `1006601001182`) |
| `entity_name_as_in_source` | нет* | название юрлица **как в источнике** (латиница/кириллица/румынский — как написано) |
| `source_url_1` | да | URL первого источника |
| `source_type_1` | да | тип источника (см. рекомендуемые значения ниже) |
| `source_date_1` | да | дата источника, `YYYY-MM-DD` |
| `source_url_2` | нет | URL второго источника (второй источник настоятельно рекомендуется) |
| `source_type_2` | нет | тип второго источника |
| `source_date_2` | нет | дата второго источника, `YYYY-MM-DD` |
| `evidence_level` | да | `A` / `B` / `C` / `D` — см. определения ниже |
| `risk_type` | да | `collusion` / `price_inflation` / `fake_competition` / `splitting` / `short_deadline` / `other` |
| `period_from` | нет | начало периода эпизода, `YYYY-MM-DD` |
| `period_to` | нет | конец периода эпизода, `YYYY-MM-DD`; если заполнено — `period_from <= period_to` |
| `first_publication_date` | да | дата, когда случай стал публично известен, `YYYY-MM-DD`; участвует во временной защите |
| `procedure_date` | нет | дата закупки/договора **по источнику**, `YYYY-MM-DD`; при ingest = дате эпизода (и `period_from`=`period_to`); участвует в окне привязки `buyer_period_only` (±30 дней) |
| `source_publication_date` | нет | дата публикации документа-источника, `YYYY-MM-DD` (отдельно от `first_publication_date`: документ мог выйти раньше/позже публикации случая) |
| `link_basis` | нет | **чем** источник привязан к процедуре: `procedure_id_in_source` / `contract_number` / `buyer_period_only`; пусто = рукописная строка MTA-0016 (в метку не входит) |
| `procedure_ref_in_source` | нет | идентификатор, названный в источнике: `ocid` / `tender_id` / номер процедуры (для `procedure_id_in_source`) либо номер договора (для `contract_number`) |
| `match_method` | нет | заполняется/перепроверяется скриптом: `idno_exact` / `name_exact` / `name_fuzzy` / `manual` / `ocid_exact` / `contract_number` |
| `match_confidence` | нет | заполняется/перепроверяется скриптом: `high` / `medium` / `low` |
| `n_procedures_matched` | нет | число сопоставленных процедур (пересчитывается скриптом) |
| `procedure_ids` | нет | список сопоставленных `ocid` через `;` (пересчитывается скриптом) |
| `verified_by_human` | да | `true` / `false` — проверено ли сопоставление человеком |
| `notes` | нет | примечания (без персональных данных частных лиц) |

\* хотя бы один из `entity_id_mtender` / `entity_name_as_in_source` обязателен:
без идентификатора сопоставление невозможно.

Рекомендуемые значения `source_type` (свободный текст, не строгий enum):
`court_decision`, `prosecutor_order`, `ncbkk_decision`, `ansc_decision`,
`aap_list`, `chamber_of_accounts`, `journalism`, `other`.

## Эпизоды (`case_episodes_raw.csv`, MTA-0017)

Одна строка = один извлечённый эпизод (источник, страница/пункт):

| Столбец | Обязательный | Правило |
|---|---|---|
| `episode_id` | да | уникальный идентификатор эпизода; становится `case_id` строки реестра |
| `source_id` | да | ключ из `case_sources.csv` (иначе эпизод отклоняется) |
| `location` | нет | страница/пункт/абзац в источнике |
| `entity_type` | да | `buyer` / `supplier` |
| `buyer` / `supplier` | нет* | субъекты **как в источнике**; хотя бы что-то одно (или `entity_id`) обязательно |
| `entity_id` | нет | IDNO, если источник его называет |
| `procedure_ref` | нет | названный в источнике идентификатор процедуры (`ocid`/`tender_id`/номер) |
| `contract_number` | нет | названный в источнике номер договора |
| `procedure_date` | нет | дата закупки/договора по источнику, `YYYY-MM-DD` |
| `risk_type` | да | как в реестре (`collusion`/`price_inflation`/`fake_competition`/`splitting`/`short_deadline`/`other`) |
| `essence` | да | суть эпизода одной-двумя фразами (становится `title_short`, ≤120 символов) |
| `quote` | нет | цитата ≤ **25 слов**; длиннее — эпизод отклоняется в отчёт (дефект извлечения, а не ошибка привязки) |

`procedure_ref` и `contract_number` **вместе не заполняются** — источник
должен называть один идентификатор; оба заполнены → эпизод отклоняется.

## `link_basis` — чем эпизод привязан к процедуре

| Значение | Условие | Разрешение (`match_method`) | Может войти в метку |
|---|---|---|---|
| `procedure_id_in_source` | заполнен `procedure_ref` | `ocid_exact`: точный `ocid`/`tender_id` либо номер ≥10 цифр из `MD-(\d{10,})$` | **да** (при high/medium и A–C) |
| `contract_number` | заполнен `contract_number` | `contract_number`: скан `data/raw/ocds_packages` (`--raw-scan`, кэш `results/methodology/contract_index.json`) либо объявленные `procedure_ids` | **да** (при high/medium и A–C) |
| `buyer_period_only` | ничего из двух не заполнено | лестница субъектов (IDNO → точное название → кандидат), **срезанная по окну периода** эпизода (`period_*` или `procedure_date` ±30 дней) | **никогда** |
| пусто | рукописная строка MTA-0016 | лестница субъектов без среза по периоду | **никогда** |

Неизвестное значение `link_basis` — жёсткий отклон строки. Запись с
`link_basis = contract_number`, которой не разрешился ни индекс, ни
объявленные `procedure_ids`, попадает в `case_unmatched.csv` (причина
`нет идентификатора`), а не в метку.

**Правило метки (MTA-0017, п. 3):**
`link_basis ∈ {procedure_id_in_source, contract_number}` **И**
`evidence_level ∈ {A, B, C}` **И** `match_confidence ∈ {high, medium}`.

## Несопоставленные эпизоды (`case_unmatched.csv`)

Причина (`reason`) — ровно одно из трёх:

| Причина | Значение |
|---|---|
| `вне корпуса` | субъект/идентификатор не найден в корпусе либо нет процедур в окне периода |
| `нет идентификатора` | нечем привязать: нет ни IDNO, ни названия, ни периода, ни названного идентификатора |
| `неоднозначно` | идентификатор нашёлся в нескольких процедурах — нужен уточняющий идентификатор или ручное подтверждение |

`detail` содержит формулировку для человека. Строки, отклонённые на
валидации (нет источника, цитата >25 слов, оба идентификатора, неизвестный
enum, дубль), в этот файл **не попадают** — они перечисляются в отчёте
`reports/case_registry_ingest.md`.

## Уровни доказательности (`evidence_level`)

| Уровень | Определение | Входит в метку проверки |
|---|---|---|
| `A` | решение суда / постановление прокуратуры или НЦБКК / решение ANSC / список AAP | да |
| `B` | отчёт Счётной палаты | да |
| `C` | журналистское расследование | да |
| `D` | упоминание без документов | **нет — в расчёты не входит** |

## Правила приёмки записей

1. **Записи без источника не принимаются.** Строка без
   `source_url_1` + `source_type_1` + `source_date_1` (или без
   `first_publication_date`) отклоняется скриптом с указанием причины и не
   участвует ни в сопоставлении, ни в метке.
2. **`evidence_level = D` в расчёты не входит**: такие записи
   сопоставляются и показываются в отчёте, но никогда не образуют позитивов
   метки (`scripts/39`, тест `test_evidence_d_never_in_label`).
3. **Надёжность сопоставления.** Порядок разрешения (`scripts/38`):
   ручное объявление (`manual`, только при `verified_by_human = true`) →
   идентификаторные привязки (`procedure_id_in_source` → `ocid_exact`,
   `contract_number` → `contract_number`; не разрешилось →
   `case_unmatched.csv`) → лестница субъекта: IDNO (`idno_exact`, `high`) →
   точное название после нормализации (`name_exact`, `high`) → неточное
   совпадение (`name_fuzzy`) только как **кандидат** с
   `match_confidence = low`; автоматически в `high` не повышается никогда.
   Записи `low` в основной расчёт не входят и считаются отдельно.
   Для `buyer_period_only` лестница дополнительно срезается по окну периода
   эпизода; если подходящих процедур в окне нет — `вне корпуса`.
   Заявленный в источнике IDNO, отсутствующий у сопоставленных процедур,
   снижает `high` → `medium` и попадает в `note` (не молча).
4. **Временная защита** (`scripts/39`): в метку и в популяцию сравнения
   попадают только процедуры с `published_date` **строго раньше**
   `first_publication_date` случая. Признаки и оценки v0 из данных после
   этой даты **не пересчитываются** — используется фиксированный
   прод-артефакт `results/tables/tender_anomaly_scores.csv`; ограничение
   (поля наград в `features.csv` — снимок поздней даты) явно указано в
   отчёте.
5. **Две версии метрик** (`scripts/39`, MTA-0017): все пригодные записи
   A–C (заголовок) и **только** `verified_by_human = true`
   (`summary["verified_only"]`). Каждая версия гейтится отдельно: <30
   позитивов или <10 кластеров — только описательная таблица без вердикта.
6. **Запрет на выдумывание.** Реестр не наполняется автоматически и не
   дополняется сетью: источники даёт только автор, `scripts/41/38` не
   выполняют сетевых запросов вообще, а флаг `--allow-network` зарезервирован
   и в текущей версии не открывает ни одного соединения; `--raw-scan` только
   читает локальные `data/raw/ocds_packages`.

## Рабочий процесс

1. Автор даёт список источников (URL + тип + дата публикации) →
   `data/external/case_sources.csv`; эпизоды извлекаются вручную в
   `data/external/case_episodes_raw.csv` (цитата ≤25 слов).
2. `.venv/bin/python scripts/41_case_registry_ingest.py` — валидация,
   вывод `link_basis`, запись сопоставленных эпизодов в реестр
   (human-столбцы не трогает, `verified_by_human=false` по умолчанию) и
   несопоставленных в `case_unmatched.csv`; отчёт
   `reports/case_registry_ingest.md`.
3. `.venv/bin/python scripts/38_case_registry_match.py` — пересчёт
   сопоставления, отчёт `reports/case_registry_match.md`,
   артефакт `results/methodology/case_registry_match.json`.
4. `.venv/bin/python scripts/39_case_registry_check.py` — проверка v0
   против реестра (метрики **в двух версиях**, базовые ранжирования,
   случайные контролы, вердикт а/б/в по правилу ANSC-проверки), отчёт
   `reports/case_registry_check.md`.
5. `.venv/bin/python scripts/40_case_registry_studies.py` — разборы случаев
   (ранги 4 детекторов, голоса, SHAP/LIME топ-3, RAG-пояснение),
   отчёт `reports/case_studies.md`.
6. `scripts/19_final_verification.py` пересчитывает числа реестра из
   артефактов и **падает при любом расхождении**.

Порядок запуска: **41 → 38 → 39 → 40** (19 — контроль).

## Ограничения метки (указываются в каждом отчёте)

- Метка смещена к крупным и громким случаям; сравнение с базовым ранжированием
  «только размер» обязательно.
- Журналистские материалы (C) ≠ доказательство нарушения.
- Результат показывает приоритизацию, а не наличие коррупции.
- «Индикатор потенциального риска, а не доказательство
  коррупции/нарушения. Требуется проверка компетентным органом.»
