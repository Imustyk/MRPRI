# MTA-0021 — протокол, зафиксированный до отбора кандидатов

База: c9c9a08. Локальный корпус только; никаких сетевых запросов, моделей, скоров, порогов или reviewer-изменений.

Целевая популяция: оспоренные процедуры MTender, опубликованные в 2022–2024, с окончательным решением ANSC; дата решения также 2022–2024. Дата решения и год публикации учитываются отдельно. Не расширять популяцию до всех закупок и не считать неподачу жалобы отрицательной меткой.

Инвентаризация охватывает все имеющиеся PDF, доступные по локальному URL→файлу манифесту; проверяются наличие, SHA-256, признаки issuer ANSC, номер 03D, дата у заголовка, резолютивный якорь и пункты. Извлечённый исход/дата/OCID/complaint_id — машинные кандидаты, не human truth. Письма ASP/заказчиков, локальные решения, 03DS/interim, unknown/withdrawn/inadmissible/terminated исключаются из пула окончательных бинарных решений. Нечитаемые сканы/неточные даты не объявляются отсутствием решения: отдельный неразрешённый backlog.

Единицы: URL для наличия; SHA-256 для уникальности PDF; decision_id + complaint_id для жалоб; подтверждённый канонический OCID для процедур; заказчик для кластерного анализа. Номера жалоб извлекаются только из резолютивных пунктов. Один PDF с несколькими жалобами не создаёт независимые процедуры. Исходы сохраняются по жалобам; смешанные исходы/разные документы одной процедуры требуют adjudication, не принудительного collapse. PDF-дубликаты группируются до подсчёта кандидатов; решение под несколькими PDF-хешами остаётся одной administrative unit. Прежние 50 URL и все их хеши исключаются из дополнительных документов, прежние процедуры отдельно помечаются как не новые.

Страты: год публикации × три категориальных исхода admitted / partially_admitted / rejected. Дополнительно сохраняется год решения и подтверждённая идентичность заказчика. Сначала полный census кандидатов без quotas/усечения; новая TEST-выборка сейчас не выбирается. Для будущего human review детерминированный порядок (год, предполагаемый исход, SHA-256), без скоров моделей. Внутри каждой страты при ограниченном бюджете — зафиксированный seed=42, известные вероятности включения, резерв неуспешной верификации по той же процедуре. Финальный holdout group-split по процедуре/решению/хешу и по возможности заказчику, никогда по URL. Существующие просмотренные случаи не считаются новым нетронутым TEST.

Исходы классов: admitted/partially_admitted → потенциально positive, rejected по существу → потенциально negative, прочие → NULL; до человеческой проверки ни один кандидат не внешняя метка. Прямая проверка связей с OCID и дат обязательна. Строгое включение требует сопоставления ID документа и жалобы, исходной страницы/цитаты, SHA-256 и опубликованной процедуры. Даты/ID из соседнего цитируемого решения не используются автоматически.

Отбор по истинному бинарному классу сам по себе сохраняет ROC-AUC только при случайном отборе внутри класса относительно скоринга/ковариат. Отбор по предполагаемому исходу noisy-экстрактора, по году, полноте текста, типу/сложности решения и подтипам admitted/partial меняет распределение сложности и состав positive, потому обычная AUC может измениться. Нужны известные inclusion probabilities/взвешивание либо честное ограничение estimand обогащённой выборкой. PR-AUC, precision, lift и prevalence нельзя переносить с outcome-balanced case-control на естественную популяцию без корректировки. Количественное сравнение моделей не выполняется.

Момент прогнозирования: publication. Признаки допустимы только при наличии первичного timestamped notice и as-of доступности; дата решения применяется только к endpoint, не к features. Границы существующего TUNE 2018–2021 / TEST 2022–2024 не сдвигать под доступные метки. Даже наличие двух классов не доказывает достаточность: сначала полнота linkage и timestamps, независимость/кластеризация, заранее выбранная точность/минимальный эффект, расчёт мощности, frozen preprocessing fit только на TUNE.
